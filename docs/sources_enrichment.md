# Предварительный список источников реальных данных для обогащения

Версия 1 от 25.10.2026. Список будет уточняться после проверки лицензий и пробного сбора.

Для каждого источника фиксируем: что берём, как получаем, правовые ограничения, ожидаемый объём, какой «пробел» датасета закрывает (по результатам EDA, см. `notebooks/01_eda_before_enrichment.ipynb`).

## 1. Текст — RuSentiTweet

Что нужно добрать по итогам EDA: класс `speech` (3,7 %) и `positive` (18 %); примеры тональности **без** явных маркеров (мат, «люблю», «спасибо»); короткие разговорные тексты на русском.

| № | Источник | Способ получения | Ограничения и риски | Объём (план) | Что закрывает |
|---|---|---|---|---|---|
| 1 | Комментарии в публичных Telegram-каналах | Telethon (официальный MTProto API), ручной отбор каналов разной тематики | Персональные данные: удаляем имена и id, храним только текст. Условия Telegram API | 1 000–2 000 | короткие разговорные реплики, все классы |
| 2 | Комментарии ВКонтакте | VK API, метод `wall.getComments` в открытых сообществах | Персональные данные — анонимизация; условия VK API | 1 000 | `speech` (поздравления, благодарности в тематических пабликах) |
| 3 | Посты Bluesky на русском | Открытый API AT Protocol, фильтр по языку `ru` | Условия сервиса; проверить, нужна ли авторизация для поиска | 500–1 000 | ближайший аналог Twitter по формату — проверка переносимости |
| 4 | Комментарии Pikabu | Ручной сбор / парсинг с соблюдением robots.txt и правил сайта | Правила сайта; аккуратно с частотой запросов | 500 | негатив без обсценной лексики |
| 5 | RuSentiment (посты ВК, та же инструкция разметки) | Скачивание с сайта проекта | **Лицензию проверить** — может быть только для исследований | до 1 000 (подвыборка) | уже размеченные реальные данные по тому же codebook |
| 6 | Ручная запись собственных реплик / опрос однокурсников | Форма, участники пишут короткие сообщения в заданных ситуациях | Согласие участников; без персональных данных | 200–300 | редкий класс `speech` |

Разметка собранного текста: по инструкции RuSentiment (codebook), 2 независимых разметчика + арбитр на расхождениях, согласие считаем через Cohen's $\kappa$ (два разметчика) и сравниваем с $\alpha \approx 0{,}505$ исходного датасета. Инструмент — Label Studio или doccano.

## 2. Изображения — TrashNet

Что нужно добрать по итогам EDA: класс `trash` (137 фото); фото в **других условиях** — не белый фон, другое освещение, предметы в руке, на улице, несколько предметов в кадре.

| № | Источник | Способ получения | Ограничения и риски | Объём (план) | Что закрывает |
|---|---|---|---|---|---|
| 1 | Собственная съёмка на смартфон | Фотографируем бытовые отходы дома, в общежитии, на улице; фиксируем условия съёмки в метаданных | Нет людей и лиц в кадре; удаляем EXIF с геолокацией | 300–600 (по 50–100 на класс) | смена домена + класс `trash` |
| 2 | TACO (Trash Annotations in Context) | GitHub pedropro/TACO, вырезаем объекты по bounding box и сопоставляем классы | Лицензии фото индивидуальные (Flickr) — **проверить**; классы нужно маппить на 6 классов TrashNet | 500–1 000 вырезок | реальные фото «в среде» |
| 3 | Wikimedia Commons | Ручной отбор по категориям (Waste, Plastic bottles, Cardboard и т. п.) | Только свободные лицензии (CC BY / CC BY-SA / PD), атрибуция в отчёте | 100–200 | разнообразие предметов |
| 4 | Фото с пунктов приёма вторсырья | Собственная съёмка контейнеров и сортированных фракций | Разрешение на съёмку, без людей в кадре | 100–200 | несколько предметов в кадре, сложный фон |

Не используем, чтобы не пересекаться с другими парами (см. таблицу курса): Drinking Waste Classification (Kaggle) и Open Images.

Разметка собранных фото: класс по codebook (материал предмета, правила для смешанных предметов, обрезанных объектов и грязной упаковки), 2 разметчика, Cohen's $\kappa$, арбитраж расхождений. Исправленные ошибки исходного датасета (3 фото, продублированных в разных классах) — отдельный раздел журнала.

## 3. Искусственное обогащение (для сравнения, этап 2+)

- **Текст:** парафраз и генерация примеров малых классов LLM (с сохранением промптов и логов), обратный перевод ru→en→ru, лёгкие текстовые аугментации (замены синонимов, перестановки, опечатки).
- **Изображения:** классические аугментации (albumentations / torchvision), замена фона после вырезания объекта, генерация и img2img диффузионной моделью.

Сравнение: одна и та же модель на (а) исходных данных, (б) + ручное обогащение, (в) + искусственное, (г) + оба вида, при равных объёмах добавки; метрики — macro-F1 на исходном тесте и на отдельном тесте из реальных данных «в другом домене».
